# personal-ai

**AI に「自分のことを覚えてもらう」ための、自分用のノートとルールの仕組み。**

[English README](README.en.md)

## これは何か
ChatGPT や Claude のような AI を、毎回ゼロから説明し直さなくても、「自分のことを知っている秘書」として使えるようにするための、個人開発のプロジェクトです。

自分のこと（仕事、予定、好み、やることなど）を、ふつうのテキストのファイル（メモ帳で開けるもの）に書いて、フォルダで整理します。AI は、そのフォルダを読んで答え、必要な時はそこに書き足します。

## 背景（なぜ作ったか）
今の AI には、不便が4つありました。
- 「覚えていること」が、サービスごとにバラバラに保存される
- 何が覚えられているのか、見えない
- サービスを替えるたびに、最初から説明し直しになる
- 覚えておける量に限界があり、情報が増えると、入りきらない

そこで、「覚えていること」を、サービスの中ではなく、自分のファイルに置くことにしました。どの AI を使っても、自分のことを知っている状態になります。量が増えても、フォルダで整理して、必要な部分だけを読ませるので、限界に当たりにくくなります。

さらに、2つのねらいがあります。
- **どの端末からでも使う**: 記憶とルールを自宅のパソコンに置いておけば、外出先の別の端末からでも、そのパソコンで AI に作業をさせられます。
- **自分専用に作り込む**: 私は、話題ごとに会話を分けず、1つの会話で、仕事、予定、買い物まで済ませています。話題ごとの違いは、ルールとフォルダで切り替えます。

## コンセプト
1. **記憶は自分のファイルに置く**: AI は、読んで書く係です。AI やモデルを替えても、記憶は残ります。
2. **任せることと、決めることを分ける**: AI は、記録、カレンダーへの登録、メールの下書きまで。送信と削除は、人が決めます。
3. **間違いは、ルールにして残す**: AI が間違えたら、同じ間違いをしないように、ルールを書き足します。

## どう使っているか（例）
- **チャットで相談する**: 質問や相談に、自分のことを踏まえて答えてくれます。調べものは、調べた根拠も一緒に残します。話の中で新しく分かったことは、その場でファイルに記録するので、次の会話でも使えます。
- 毎朝、今日の予定、期限、やることを、1画面にまとめてくれる
- 毎日、AI や IT のニュースを選んで、「事実」と「推測」を分けて保存してくれる
- 毎週、フォルダの構成、ルール、記憶、定期実行を見直して、運用の無駄や矛盾を減らす提案をしてくれる（小さな整理は、自分で実行する）

## 普通のチャットと、何が違うか
| | 普通のチャット | personal-ai |
|---|---|---|
| 自分のこと | 毎回、説明が必要（覚える機能があっても、中身は見えにくい） | 自分のファイルに書いてあるので、説明し直さなくてよい。中身は、見て、直せる |
| 新しく分かったこと | 会話が終わると、使いにくくなる | その場でファイルに記録するので、次の会話でも使える |
| できること | 答えるだけ | 答えるだけでなく、記録、カレンダーへの登録、メールの下書きまで行う（送信と削除は人） |
| 間違い | 同じ間違いが、また起きやすい | 間違いをルールにして残すので、同じ間違いを減らせる（例: 時刻は必ず確認する） |
| 先回り | 話しかけた時だけ動く | 毎朝のまとめなど、決めた時間に自分で動く |
| 乗り換え | サービスを替えると、最初からやり直し | AI を替えても、同じファイルを読ませれば続けられる |

注意: 「普通のチャット」は、一般的な使い方の話で、サービスや設定によって違います。効果（回答の速さや正確さ）は、まだ測っていません。

ここから下は、仕組みの詳しい説明です（エンジニア向け）。

> English summary: A personal "memory layer" for AI agents, built on plain Markdown files and Git. Instead of each AI service keeping its own hidden memory, the memory lives in my own files, and any agent can read and write it. The agent records, schedules and drafts; a human sends and deletes. Mistakes become written rules. This repository shows the design only; it contains no personal data, and all examples are fictional.

## 設計の原則
1. **記憶はファイル、AI は読み書きする側**: 正本は Markdown。AI やモデルを替えても、記憶は残ります。人が読めて、直せて、移せます。
2. **読む範囲を絞る**: 番号つきのフォルダと索引で、必要なものだけを読ませます。全部は読みません（トークンの節約と、速さが狙い。効果の測定は、これからです）。
3. **実行と承認を分ける**: AI が実行してよいのは、記録、カレンダーへの登録、メールの下書きまで。送信と削除は、人が行います。
4. **未確認を、事実のように書かない**: 事実、推測、未確認を分けて書かせます。根拠のない手順や数字は、書かせません。
5. **失敗は、ルールにして残す**: 運用で起きた間違いを、AGENTS.md や rules に書き足します。

## 構成（例）
```
AGENTS.md          # 正本。読む順番と、絶対に守るルール
CLAUDE.md          # Claude Code 用。AGENTS.md を @import で橋渡し
00-rules/          # 考え方、回答モード、情報源、出力形式、置き場所、記録の手順
01-private/        # 機微な情報（git 管理外。外部に出さない）
02-knowledge/      # 本人に関する事実。AI が仕事中に読む
03-output/         # 作った成果物
04-resources/      # 調べた記録・外部資料の原本（編集しない）
05-todo/           # 未着手のタスク
99-trash/          # 削除の代わりの退避先
```
番号つきのフォルダにしたのは、AI が探す回数を減らすためです。

## 実行と承認の境界
| 操作 | AI | 人 |
|---|---|---|
| 記録・更新（Markdown） | 実行 | |
| カレンダーへの登録 | 実行 | |
| メールの下書き | 作成 | 送信 |
| ファイルの削除 | 退避（99-trash へ移動） | 完全な削除 |
| GitHub などへの push | しない | 明示した時だけ |

## 失敗から作ったルール（例）
実際に起きた間違いと、ルールにした内容です（文面は、例として書き換えています）。

| 起きたこと | ルール |
|---|---|
| 時刻を推測で答えた | 時間・予定・「今」に触れる前に、必ず `date` で確認する |
| 「機能の記載がない」で、調査を止めた | 固有用語、公式サポート、前の機種、ブラウザ、原文、本人への確認の順に調べる。見つからなければ、調べた範囲を書く |
| ツールが失敗した時に、エラー文を言い換えて原因にした | 先に、自分で実行できる診断をして、確認できた事実だけを原因として言う |
| 事実と推測が混ざった | 「事実／推測／未確認」を分けて書く |
| 確認していない手順や画面名を、もっともらしく書いた | 分かっていることと分からないことを分ける。必要なら、画面を見せてもらう |

## 定期実行の例
- 毎朝: 予定、期限、チェックリストを、1画面にまとめる
- 毎日: AI・IT のニュースを選んで、事実と推測を分けて保存する
- 毎週: フォルダ構成、ルール、記憶、定期実行、バックアップを見直して、運用を最適化する（小さな整理は実行、大きな変更は提案のみ）

手順書は `00-rules/` に置き、結果は `03-output/` に保存します。

## 使い方（自分用に作る場合）
1. 上の構成で、空のフォルダを作る（`01-private/` は、`.gitignore` に入れる）
2. `AGENTS.md` に、索引と、守るルールを書く
3. 既存の記憶（メモ、AI サービスの履歴）を、事実ごとに `02-knowledge/` へ移す
4. 運用で間違いが出たら、ルールに書き足す
5. 慣れたら、定期実行を足す

## 運用の実績（2026-10-24 時点、自分の環境）

## 公開していないもの
個人データ、実際の記録、認証情報は、このリポジトリに含まれません。例は、すべて架空のものか、書き換えたものです。
